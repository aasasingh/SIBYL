# Phase 3 findings — no usable recalibration edge, and a test too weak to say more

Reproduce, in order:

```bash
uv run sibyl backfill --venue polymarket --months 24 --max-pages 400 --price-markets 3000
uv run sibyl calibrate --n-boot 400 --n-folds 4 \
    --out research/calibration-report.txt --json-out research/calibration.json
uv run sibyl eiv                                    # measurement-error attenuation
uv run sibyl power --seeds 80 --json-out research/power.json
uv run sibyl tables                                 # regenerates every table below
```

Data: **159,182 hourly rows / 1,977 resolved markets / 608 events** on
Polymarket International, 63 (domain x horizon) cells. Note the event count:
608 is the independent-evidence count for this fit, not 1,977. (The wider
resolved universe in the ledger holds 10,846 markets across 1,017 events; the
priced subset is thinner per event because tape pulls sampled markets
pseudo-randomly rather than whole events.) Full text output in
[calibration-report.txt](calibration-report.txt) and
[power-analysis.txt](power-analysis.txt).

> `calibration.json` and `power.json`. An earlier draft contained a
> hand-typed walk-forward table whose numbers were invented; it was caught,

## Verdict

**Phase 3's acceptance criterion is not met**, and — the more important
finding — **the test is too weak to support a stronger claim than that.**

The metric is the **Brier score** (mean squared error of the probability
forecast), against the raw quoted price as baseline, out of sample, split on
whole events.

## 1. Errors-in-variables: measured, not argued

An earlier draft claimed that a negative result on optimistic data is a
stronger negative. That holds for a P&L backtest and is **false for a
calibration fit**: classical measurement error in the regressor attenuates
its coefficient *toward zero*,

> plim b_hat = lambda * b_true,  lambda = Var(x_true) / Var(x_observed)

so tape noise pushes the slope toward "no compression" and the kill could be
a false negative.

**(a) How big is the noise?** For a random walk plus independent noise,
`Var(x_{t+k} - x_t) = k*sigma2_signal + 2*sigma2_noise`, so regressing the
mean squared k-step difference on k identifies the noise from the intercept
([`calibration/eiv.py`](../src/sibyl/calibration/eiv.py)). On the real hourly
bars (1,475 series, regression r2 = 0.95):

| quantity | value |
|---|---|
| noise sd in logit(p) | **0.434** |
| Var(observed logit p) | **10.32** |
| reliability lambda | **0.982** |
| noise share of regressor variance | **1.8%** |

Attenuation is real but **small**, for a structural reason: the regressor's
variance is dominated by *cross-market* price dispersion (logit spans about
+/-4.6 from 1c to 99c), which dwarfs *within-market* measurement noise.
Per-cell lambda runs 0.90-1.00, corrections move slopes by 1-3%
(politics/1mo+ 1.544 -> 1.567), and **zero cells cross b = 1** after
correction (`sibyl eiv`).

**(b) The distinction that actually matters.** For *prediction from an equally
noisy input*, the attenuated coefficient is the **correct** one: if a noisy
price is what you observe at trade time, `b_hat` is what maps it to a
calibrated probability, and "correcting" it would make the forecast worse.
EIV correction answers *"is the market really compressed?"* (inference), not
*"what should I multiply this quote by?"* (prediction).

The real problem is therefore not attenuation but a **mismatch**: trained on
tape noise, deployed against quote noise. Those have different variances, so
neither `b_hat` nor `b_corrected` is the right deployment coefficient, and no
arithmetic on tape data can produce it. Only recorded books can — which is
why `sibyl record` is now running continuously.

## 2. Clustering was at the wrong level — fixed, and it changed the answer

Intervals and fold splits were clustered on the **market**. They belong on the
**event**: markets inside an event share an outcome, because in a NegRisk set
exactly one resolves YES and the rest are mechanically implied. Not an edge
case here:

| quantity | value |
|---|---|
| resolved markets | 10,846 |
| distinct events | 1,017 |
| markets per event (mean) | **10.66** |
| largest single event | **122 markets** |
| negRisk markets | 7,929 of 10,846 |

Both uses were corrected: the bootstrap resamples whole events, and the
walk-forward splits whole events. The split mattered independently of the
intervals — splitting a mutually-exclusive set across folds hands the test
fold its own answer ("train on A won" resolves "did B win?").

Measured effect on the intervals (36 cells, 300 draws each): **widened in 22
cells, narrowed in 14, median width ratio 1.041.** Three verdicts changed;
`politics/3-6h` went from [1.02, 3.24] to [0.95, 8.80] and lost tradeability.

Two precisions worth keeping:

- The magnitude is modest (~4% median widening), not the order of magnitude a
  naive "10x fewer independent units" argument predicts.
- **Event clustering is not universally wider.** Synthetic designs showed both
  directions: when price variation lives *within* an event and the outcome is
  shared, each event is an informative within-event comparison and bundling
  can *tighten* the interval. The test suite asserts the counting and
  no-leakage invariants rather than a direction.

Net effect: tradeable cells **5 -> 4**, and `politics/1mo+` — the one survivor
matching a published prior — dropped out.

## 3. The test's power — the finding that reframes everything

An earlier draft ran **one** simulation per condition and concluded "a true
slope >= 1.3 would still have been detected". That rested on a single random
draw, and the experiment's own null condition came out positive in 4 of 4
folds — a false positive that showed exactly how far one draw can mislead.

Re-run with 80 seeds per condition, using the report's own decision rule
(mean improvement > 0 AND more than half the folds positive), with event-level
outcome dependence in the generator and logit noise at the measured 0.434:

<!-- BEGIN:power -->
<!-- generated by `sibyl tables`; do not edit by hand -->
| true b | fitted b | mean improvement | detection rate | verdict |
|---|---|---|---|---|
| 1.0 | 0.853 | -0.000079 | 31.2% (**false positive rate**) | null — this is the floor |
| 1.1 | 0.934 | -0.000621 | 15.0% (detection) | **undetectable** |
| 1.2 | 1.017 | -0.000619 | 13.8% (detection) | **undetectable** |
| 1.3 | 1.100 | -0.000305 | 22.5% (detection) | **undetectable** |
| 1.5 | 1.252 | +0.000947 | 56.2% (detection) | **undetectable** |
| 2.0 | 1.605 | +0.005600 | 96.2% (detection) | detected |

80 seeds per condition, 4 folds, logit-space noise sd 0.434.
Smallest slope reaching 80% power: **b = 2.00**
<!-- END:power -->

Three things follow, and they are more interesting than the kill itself:

1. **The decision rule has a ~31% false positive rate.** "Mean > 0 and most
   folds positive" fires on nothing roughly a third of the time. It is a weak
   rule, and any single positive result from it means very little.
2. **Only b = 2.0 is reliably detectable.** That is far outside the range the
   data suggests (in-sample mu = 1.203), so the procedure cannot resolve the
   effect size actually in question.
3. **Detection at b = 1.1-1.3 (14-23%) is *below* the null rate (31%).** This
   is not just low power, it is a systematic bias: at moderate true slopes the
   attenuated fit is miscalibrated enough that applying it makes
   out-of-sample Brier slightly *worse* than the raw price, so the test
   actively reports "no improvement" when a real effect exists.

So the honest reading of the real -0.0030: it is **consistent with anything
from b = 1.0 to roughly b = 1.4**, and it is also what point 3 predicts if a
moderate effect is present but the fit is attenuated. The result rules out a
*large* exploitable compression. It does not rule out a moderate one.

Why the earlier framing was wrong in both directions: it over-claimed power
("b >= 1.3 would have been detected") and under-stated the procedure's
fragility. Fold-to-fold variation in the real data spans **-0.018 to +0.017**
against effects worth ~0.001-0.006 — several times the size of the signal
being looked for. Four folds cannot resolve that, and neither can eight.

**What would make this test usable:** a decision rule calibrated against the
null distribution above (rather than "mean > 0"), many more independent
events, and a regressor measured the way it will be at decision time — i.e.
recorded quotes. The first two are arithmetic; the third is why the recorder
matters.

## The most useful by-product: a mid-range inefficiency that was not real

The first run's reliability table showed observed outcomes running **+15
percentage points above** the quoted price mid-range — which would be the
largest inefficiency ever recorded in this asset class. It was an artifact of
counting rows instead of bets.

Count each market once and the mid-range gap collapses to roughly zero.
**Polymarket is well calibrated between 0.35 and 0.65.** The row-level gap
came from long-lived markets contributing hundreds of correlated rows each —
spec §8's serial-correlation trap arriving through a descriptive statistic
rather than through a confidence interval.

### The extremes remain unresolved, deliberately

The market-level column shows a large *negative* gap at the top. Read naively
that says favourites are badly *over*priced, reversing the longshot bias. Do
not read it naively — neither column is the right statistic:

- **Row-level** over-weights markets that sat at a price for a long time.
- **Market-level** counts a market that merely *touched* a high price for an
  hour before collapsing the same as one that sat there 500 hours and won.

The truth is between them and needs duration weighting that neither
implements. Honest summary: the mid-range is well calibrated under any
weighting; the extremes are not resolved by this analysis.

## Remaining weaknesses

From [data-limitations.md](data-limitations.md):

1. **Prices are a trade tape, not a quote book** — unfixable retrospectively,
   quantified in section 1 rather than hand-waved.
2. **17.7% of markets are missing their first half of life** (newest-first
   tape, capped at 3,000 trades/market), so long-horizon cells are
   selectively drawn from less-traded markets.
3. **One venue.** The spec's slopes are Kalshi; this is Polymarket
   International. Disagreement may be two different markets, not a failed
   replication.
4. **Keyword domain labels**, so a cell may contain markets that do not belong
   in it. `other` appearing among the survivors is a warning sign.
5. **The power simulation is an approximation.** It makes within-event
   outcomes comonotonic, whereas a real NegRisk set is mutually exclusive
   (negatively dependent). Both reduce independent evidence below the market
   count; they are not the same structure.

## What this changes downstream

- **Phase 5 must not ship directional recalibration as its primary alpha.**
  The system already fails safe.
- **The maker-rebate idea (§2.3.1) is untouched by this result** and is the
  strongest remaining candidate, because it does not require being right
  about anything. It is also the hardest thing to paper-trade honestly: the
  entire question is adverse selection, and a simulator that fills whenever
  the price touches your level assumes the best possible case. See
  [fill-model-design.md](fill-model-design.md).
- **`sibyl record` runs continuously**, with coverage segments so the fill
  model can refuse to simulate across gaps rather than interpolate them.
- **Phase 4 is descoped**: cross-venue identity is pointless when cross-venue
  execution is unavailable. A subset-relation graph *within* Polymarket still
  feeds single-venue parity arbs, and is worth doing later, if at all.

## Falsifiable next steps

1. **Record books continuously** (running). The only route to a result that is
   not an upper bound, and the only fix for the noise mismatch in 1(b).
2. **Build the fill model** against recorded data before simulating any maker
   strategy.
3. **Calibrate the decision rule against the null** measured in section 3,
   instead of "mean improvement > 0".
4. **Deepen the tape** and re-run; if long-horizon cells move materially,
   those numbers were a sampling artifact.
5. **Duration-weighted reliability**, to settle the extremes question.

A system that reliably tells you it has no usable edge — and tells you when
its own test was too weak to know — is worth more than one that tells you it
has one.
